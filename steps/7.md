## （2025 年暑期）静态博客生成器

**目标**：使用 Node.js 实现一个静态博客生成器。<br />
**难度**：中等

### 功能要求

你的生成器需要能够处理指定目录下的 Markdown 文件，并输出一个结构完整的 `dist` 目录，其中包含可以被直接部署的 HTML, CSS 等静态资源。

### 页面结构

- **首页（文章列表页）**：`index.html`（`/page/{页码}/index.html`）
  - 集中展示所有博文的标题、摘要和发布日期。
    - 【**加分项** · 易】在前端结合一定的处理方式和 JavaScript 脚本实现发布日期显示的「X 天前」格式。
  - 博文列表必须按照 front-matter 中指定的 `date` 字段进行降序排列（即最新的文章在最前）。
    - 【**加分项** · 易】通过读取文件系统上的文件修改时间来确定文章最近的修改时间，并在文章列表和详情页中显示。
  - 文章数量过多时，应实现分页逻辑，每页展示固定数量（如 15 篇）的文章，并提供清晰的「上一页」「下一页」导航。
    - 【**加分项** · 中】实现跳转到首页、前后 X 页、末页的功能。<br />
      ![](./7/pagination.png)<br />
      如图中紫色框线框住的区域所示。<br />
      实现的时候需要注意窄屏设备的适配，确保在手机上也能正常使用。
- **文章详情页**：`/posts/{文件名}/index.html`
  - **URL 结构**：每篇文章应生成一个独立的目录，路径根据其 Markdown 源文件的文件名（不含扩展名）决定。例如，hello-world.md 将生成 /posts/hello-world/index.html。
  - **内容渲染**：
    - 标题：从 front-matter 中获取 `title` 字段。
    - 正文：将 Markdown 文件内容完整渲染为 HTML。
    - 元信息展示：页面上需要清晰地展示文章的发布日期（来自 front-matter）。
      - 【**加分项** · 易】通过读取文件系统上的文件修改时间来确定文章最近的修改时间，并在文章列表和详情页中显示。

### 技术要求

- 首页和文章详情页必须共享相同的页头（Header）和页脚（Footer）。你必须使用模板引擎或自定义的模板函数来实现布局复用，而不是在多个文件中复制粘贴 HTML 代码。
- 项目必须提供一个清晰的入口脚本（如 `build.js`），通过 `node build.js` 命令即可完成整个站点的构建过程。
- 你需要编写基础的 CSS 来美化你的博客。成品不要求设计感惊艳，但必须保证结构清晰、排版工整、阅读体验良好。<br />
  ![](./7/oi.baoshuo.ren_20220309.png)<br />
  ![](./7/oi.baoshuo.ren_luogu-p7913_20220309.png)
- 所有 Markdown 文件顶部可以包含 YAML front-matter 块，用于记录文章的元信息。请使用专门的解析库来解析这些 front-matter 数据，没有数据时可以使用文件名和文件系统上的文件元信息作为替代。<br />

  ```markdown
  ---
  title: "我的第一篇博客"
  date: "2025-07-20"
  ---

  这里是文章的正文内容...
  ```

### 技术选型提示

下面给出了一些推荐的技术选型，但你也可以根据自己的喜好选择其他工具。

- **Markdown 渲染器**
  - [marked](https://github.com/markedjs/marked)：一个快速、轻量级的 Markdown 解析和编译库。
  - [markdown-it](https://github.com/markdown-it/markdown-it)：功能强大且支持插件扩展，可以轻松实现代码高亮、TOC 等高级功能。
- front-matter 解析器
  - [gray-matter](https://github.com/jonschlinkert/gray-matter)
  - [parse-md](https://github.com/rpearce/parse-md)
- **模板引擎**
  - DIY 方案：你可以尝试自己用字符串拼接或模板字符串实现一个最简陋的模板函数，但这只推荐在项目初期用于理解原理。
  - 成熟方案（推荐）
    - [EJS](https://github.com/mde/ejs)：语法类似原生 HTML，学习成本低。
    - [Nunjucks](https://mozilla.github.io/nunjucks/)：功能强大，语法类似 Python 的 Jinja2，支持继承、宏等高级特性。

### 加分项

完成核心功能后，可以尝试实现以下加分项来提升项目的完整性和你的技术能力。

#### （简单）生成 Sitemap

- **目标**：在构建时自动生成 `sitemap.xml` 文件，这对于 SEO 非常重要。
- **实现**：遍历所有文章页面，将它们的 URL 列表按 Sitemap XML 格式写入文件。

#### （简单）数学公式支持

- **目标**：支持在 Markdown 中使用 LaTeX 语法编写数学公式。
- **实现**：可以使用 [KaTeX](https://katex.org/) 或 [MathJax](https://www.mathjax.org/) 来渲染数学公式。

#### （中等）TypeScript 支持

- **目标**：使用 TypeScript 编写整个项目，为文件 I/O、数据处理等环节提供类型约束，提升代码健壮性和开发体验。
- **实现**：可以使用 [ts-node](https://github.com/TypeStrong/ts-node#programmatic) 直接运行 .ts 脚本。

#### （中等）标签功能

- **目标**：解析 front-matter 中的 `tags` 字段，并为每个标签生成一个独立的列表页面（如 `/tags/Node.js/index.html`），展示所有包含该标签的文章。

#### （困难）纯前端搜索功能

- **目标**：实现一个无需后端的站内搜索功能。
- **实现思路**：在构建时，将所有文章的标题、标签和纯文本内容处理后，生成一个大的 `search.json` 文件。在前端，通过 `fetch` 加载此 JSON 文件，并使用 Lunr.js 或 Fuse.js 等库来实现高效的客户端搜索。

## （2026 年暑期）AI Chatbot

**目标**：使用 React 或 Vue 框架结合大模型 API，开发一个支持流式输出和结构化渲染的 AI 智能对话助手。<br />
**难度**：中等偏上

### 功能要求

实现一个基于 React 或 Vue 的 AI Chatbot 网页，能够与用户进行自然语言对话。

### 页面结构

- **主聊天页**：`/`（单页应用主路由）
  - **侧边栏（会话列表）**：
    - 展示所有的历史会话记录（如“新对话”、“帮我写代码”等）。
    - 提供“新建对话”的按钮。
  - **主聊天区域**：
    - 集中展示当前会话的消息流。User（用户）和 Assistant（AI）的消息气泡在视觉、排版上需要有明显的区分（例如类似微信左右排布，或提供不同的头像与背景色）。
    - 消息内容支持 Markdown 格式的富文本渲染（包括代码块、列表、加粗等）。
    - **自动滚动**：在 AI 流式回复的过程中，聊天窗口必须能够自动滚动到最底部，保持最新生成的内容可见。
  - **底部输入区域**：
    - 包含一个多行文本输入框和发送按钮。
    - 支持快捷键操作（如 `Enter` 发送消息，`Shift + Enter` 换行）。
    - 发送消息后，输入框应自动清空并保持聚焦状态。
- 设置页（可选）：`/settings`
  - 允许用户配置一些基本选项，如选择使用的语言模型（如果你实现了多个模型的支持）。
  - 将 API_KEY 等设置项存储在 localStorage 中。

### 技术要求

- **组件化思维**：必须使用 React 或 Vue 进行开发。要求将页面合理拆分为多个可复用的组件（例如：`Sidebar`, `MessageList`, `MessageBubble`, `ChatInput` 等），杜绝将所有代码塞在一个文件里。
- **流式输出（核心）**：对接大模型 API 时，不要等待模型全部生成完毕后再渲染页面，要实现打字机般的逐字输出效果。
- **状态管理与持久化**：
  - 将所有对话数据（角色、内容、时间戳等）保存在前端的全局状态中。
  - 必须利用浏览器的 `localStorage` 或 `IndexedDB` 缓存对话记录，确保刷新页面或重新打开浏览器后，之前的聊天状态和历史会话依然存在。
- **安全与跨域**：由于直接在前端请求大模型 API 会面临跨域（CORS）和 API Key 泄露的风险，请自己在本地使用 Node.js 搭一个简易的转发服务器，作为后端提供服务，具体可以参考第六轮 Node.js 入门相关内容。

为了方便，可以直接使用硅基流动平台的 AI 模型接口：<https://cloud.siliconflow.cn/i/KsXlFfvn>

### 技术选型提示

下面给出了一些推荐的技术选型，你可以根据自己熟悉的生态进行搭配。

- **前端框架与状态管理**
  - React 生态：React + Zustand/Redux
  - Vue 生态：Vue 3 + Pinia
- **流式 Markdown 渲染器与代码高亮工具**
  - 查找相关支持流式渲染的 Markdown 解析库，或者在现有库的基础上进行改造。
- **流式请求处理**
  - 原生 `fetch` 结合 `Response.body.getReader()`；
  - 方便使用的第三方库。

### 加分项

完成核心功能后，可以尝试实现以下加分项来拉开差距，展现你的前端工程化能力。

#### （简单）请求中断功能

- **目标**：在 AI 正在长篇大论输出时，提供一个「停止生成」按钮。
- **实现**：利用 `AbortController` API 绑定到你的 `fetch` 请求上，点击按钮时触发 `abort()` 中断底层网络请求。

#### （中等）多会话管理与路由

- **目标**：实现完整的侧边栏多会话管理。
- **实现思路**：引入 `React Router` 或 `Vue Router`。每个独立的会话都有自己的专属 URL（如 `/chat/{sessionId}`）。切换侧边栏会话时，不仅主区域内容要切换，URL 也需要同步更新，且支持从特定 URL 直接载入对应的历史对话。将会话数据结构设计得合理，确保在切换会话时能够高效地加载和渲染对应的消息记录，可以考虑存储到 indexedDB 中。

#### （困难）结构化输出与自定义组件渲染 (Tool Calling)

- **目标**：突破纯文本的限制，让大模型在特定场景下输出可视化卡片。
- **实现思路**：
  1. 通过 Prompt 提示词，要求大模型在被问到特定问题（如“帮我生成一个用户卡片”或“展示一份柱状图数据”）时，输出特定格式的标签（例如 `<user-card name="张三" />` 或一段 JSON 字符串）。
  2. 前端在解析流式文本时，需要编写相关拦截器，识别并提取这种特殊格式。
  3. 将提取出的数据注入到你自己封装的 React/Vue **自定义组件**中进行渲染（例如渲染出一个带有样式的卡片、或者一个 Echarts 图表），而不是将其作为普通文本展示出来。

#### （困难）多模态或语音交互

- **目标**：让你的应用支持图像识别或语音对话。
- **实现**：
  - **图片**（较简单）：允许用户在输入框上传图片，转换为 Base64 后随文本一起发送给支持视觉模型（Vision）的 API。
  - **语音**（复杂）：利用浏览器的 `Web Speech API` 实现点击麦克风后语音转文字输入，或者调用大模型的 TTS（Text-to-Speech）接口将 AI 的回复朗读出来。
